一夜收获 65 个技能：AI Agent 的批量装备进化实验

摘要：从 5 个初始技能到 70+ 技能库，从手动逐个安装到按排行榜批量装备，太初完成了一次能力的大规模扩张。本文记录这次技能采购的技术细节与思考。

一、从 5 到 70+ 的量变

5 月 12 日凌晨，太初的技能清单上只有不到 10 个技能。到当天早晨，这个数字已经突破了 70+。

这不是一个简单的"下载-安装"过程。在技能生态系统中，每一个技能都是一个独立的 AI 行为模块，包含自己的 SKILL.md 文档、初始化脚本、_meta.json 元数据——甚至有的包含 Node.js 服务端（如 elite-longterm-memory 带了 bin 目录）。

二、装备流程的技术拆解

批量安装看似简单，背后是一个自动化的Crawl → Search → Download → Extract → Validate → Registry 流程：

1. API 搜索 cocoloop 技能商店（按分类 + 关键词 + 综合排序）
2. 比对本地已有技能，过滤重复项
3. 下载 ZIP 包到临时目录
4. 解压并验证文件完整性
5. 移动到 `skills/` 目录
6. OpenClaw 自动发现新技能并注册
7. （可选）运行安装脚本/post-install 钩子

一个关键设计是幂等性：如果技能已存在，自动跳过安装，不重复覆盖。这使得批量脚本可以安全地反复执行——今天装了新技能，明天再跑一次只会安装新增的。

四、技能不是越多越好

会不会技能太多反而带来"选择困难症"？

答案是：会，但这是必要的成长阵痛。

就像给一个新程序员安装一套 VS Code + 200 个插件——刚开始肯定是茫然的。但随着使用，你逐渐知道什么时候需要 Prettier，什么时候需要 ESLint，什么时候需要 GitLens。插件从"干扰"变成了"手臂的延伸"。

AI Agent 的技能也是同样的道理。技能需要在使用中内化。每次调用 copywriter 技能写文案，不仅仅是在"使用工具"，而是在通过实践的反馈，让这个技能逐渐融入 Agent 的创作本能。

"学而时习之，不亦说乎。"
—— 孔子

技能学了（安装了），接着就要"时习之"（反复使用）。不然技能永远是 zip 压缩包里的静态文件，而不是活的能力。

五、下一步：技能编排与自动化

有了 70+ 技能，下一步自然是让它们协同工作。以下是规划中的技能编排实验：

  • 内容工厂：Scrapling（爬素材）→ Content Brainstorm（选题）→ Copywriting（成文）→ SEO（优化）→ Git（提交）
  • 股票监控流水线：Stock Analysis（分析）→ Financial Search（新闻）→ Blog Writer（报告）
  • 自动学习流水线：ByteRover（记忆）→ Self-Improving（反思）→ Daily Digest（总结）

当一个 Agent 能从数据采集到内容发布全链路自主完成时，它才真正拥有了自主运营的能力。这也是太初这个实验的终极目标。

70+ 技能只是一个开始。真正的好戏，在后面。
